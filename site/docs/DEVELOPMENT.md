# 项目开发文档

## 1. 目标与边界

本项目使用 VitePress 生成可部署到 GitHub Pages 的静态博客。开发服务器与正式构建共用内容读取、Markdown、MathJax、TikZ、主题和路由配置；本地预览不是另一套渲染器。

实现遵守以下边界：

1. 每篇文章是一个独立文件夹，Markdown、图片和附件同目录保存。
2. 文章网址只由 `articleId` 决定，分类变化不改变网址或文章文件夹。
3. 分类固定为三级，每一级都有分类页，文章只指向第三级。
4. `category-tree.yml` 是分类结构、显示名称和顺序的用户维护入口。
5. 文章 Markdown 开头的 `category` 是文章归属的源数据。
6. 分类页面 Markdown 的正文是分类介绍的源数据；其路径、标题和顺序元数据由分类同步器维护。
7. 分类树、分类页列表、面包屑、前后文章、标签和搜索均从上述源数据生成，不保存第二份可编辑文章清单。

### 1.1 累积产品验收基线

本节记录用户已经确认的全部产品要求。所有要求始终同时有效：后提出的要求只补充或细化已有要求，前后要求都不会因此失效；只有用户明确指出取消或替换某一条要求时，才改变那一条要求。实现、文档和内部重构都必须同时满足这里列出的全部要求，不得自行挑选、删减或用一项要求交换另一项要求。回归检查只负责发现实现是否违反要求，不参与决定要求是否保留。

1. 网站始终使用浅色背景，整体视觉以 Kerodon 的克制、清楚和精致为基准，但不使用其豚鼠形象；首页不得用接近一整屏的空白介绍区推迟主要内容。
2. 网站固定使用三级分类。第三级表示一个文章系列；每一级都有内生的分类页，分类页不是用普通博客文章冒充的索引。
3. 电脑端持续显示左侧全站分类树和右侧本文标题目录；手机端两者默认收起并可随时打开。当前位置、分类上下级、同系列文章和标题跳转必须明确。
4. 分类名称不自动加入 `Part 1`、`1.1` 等无内容意义的序号。分类树是用户可直接阅读和编辑的纯文本文件，页面结构从它与文章设置生成。
5. 新文章默认进入待分类系列。文章、图片、PDF 和其他附件位于同一个文章文件夹；文章物理位置与网页分类独立，修改分类不移动正文或附件。
6. 文章中的 `category` 可以直接改变归属；分类树可以安全完成新建、改名、移动、合并和删除。分类修改必须先检查、失败回滚并可撤销最近一次成功修改。
7. Markdown、公式和 TikZ-CD 的源文件写法与 Markdown Preview Enhanced 的 `markdown_it` 预览保持一致。TikZ 代码块使用 `tikz {embedFontCss=true}`；网页不得要求维护另一份内容格式。
8. 行内公式保持正常排版；只有真正溢出的独立公式局部横向滚动。交换图保持自然比例，小图不得被无故缩小，大图需要在正文宽度内自适应，且不能扩大整页宽度。
9. 头像、网站名称、首页说明、文章字号和主页字号可在 `site.yml` 修改；文章与主页各有手机、电脑两个边界值，中间屏幕宽度平滑变化。头像使用普通图片文件，不依赖固定花体字母。
10. 本地预览需要快速热更新，保存文章、资源、分类或设置后可见结果；本地预览、静态产物预览和 GitHub Pages 使用同一套内容与渲染配置。
11. 公开命令在 PowerShell、Windows 命令提示符、Git Bash 和 VS Code 集成终端中含义一致；必须有帮助、启动、停止、端口冲突处理和明确错误信息。命令不能占用或混淆 npm 自有命令。
12. 用户说明书与开发文档分开。用户说明书先说明操作及其结果，并在操作首次涉及结构时同时解释必要结构；文字需要简洁、句子成分完整、术语无歧义，不包含通用 Markdown 教程。开发文档包含实现、边界、失败处理和验收方法。
13. 每次修改按影响范围复测，但至少不得破坏首页、三级分类页、文章页、标签、搜索、桌面双目录、手机抽屉、公式溢出、TikZ 缩放、热更新、服务器关闭和 GitHub Pages 构建。涉及布局时同时检查 2048×984 桌面视口与 390×844 手机视口。

```text
│  ├─ categories.mjs
│  ├─ blog.mjs
│  ├─ dev-server.mjs
│  ├─ preview-server.mjs
│  ├─ site-lib.mjs
│  ├─ check-content.mjs
│  ├─ render-site-settings.mjs

│  └─ DEVELOPMENT.md
└─ content/
   ├─ articles/<articleId>/<articleId>.md
   ├─ drafts/<articleId>/<articleId>.md
   ├─ categories/<level-1>/<level-2>/<level-3>/<level-3>.md

   ├─ categories/[__category_path]/
   ├─ public/brand/
   └─ .vitepress/
      ├─ config.mjs
      └─ theme/
```

`.category-history/` 保存最近一次分类事务的本地撤销记录和最近确认过的文章归属；`.trash/` 保存被文章或草稿命令移除的完整文件夹。两者均被 Git 忽略。

`content/.vitepress/dist/`、VitePress 缓存、`.cache/tikz/`、生成的 TikZ 字体 CSS 和站点设置 CSS 都是生成物，不应手工修改。

## 3. 内容模型

### 3.1 文章

文章必须位于 `content/articles/<articleId>/<articleId>.md`。同目录文件由 Markdown 相对路径引用，因此 Markdown Preview Enhanced 和网站生成器读取同一份资源。

```yaml
---
title: <文章标题>
date: <年-月-日>
tags: [<标签>]
articleId: <文章文件名>
category: <一级>/<二级>/<三级>
order: <正整数>
categoryNote: <可选说明>
---
```

`articleId`、目录名和 Markdown 文件名必须一致。`category` 必须包含三个有效 ID。`order` 只控制同一第三级分类中的文章顺序；缺省值排在显式顺序之后。`categoryNote` 只进入分类页列表。

### 3.2 分类树

`category-tree.yml` 的结构如下：

```yaml
changes: []
tree:
  - id: mathematics
    title: 数学
    children:
      - id: algebra
        title: 代数
        children:
          - id: galois-theory
            title: Galois 理论
```

数组位置定义同级顺序，因此用户不需要维护数值序号。每个 `id` 使用 `[A-Za-z0-9]+(?:-[A-Za-z0-9]+)*`，分类完整路径忽略大小写后也必须唯一。第一级和第二级必须有 `children`；第三级不能再有下级。

`changes` 只声明无法从最终树安全推断的节点身份变化：

```yaml
changes:
  - rename: { from: <原完整路径>, to: <新完整路径> }
  - move: { category: <当前完整路径>, under: <新上级完整路径> }
  - merge: { from: <来源三级路径>, into: <目标三级路径> }
  - remove: { category: <空分类或空分支路径> }
```

操作按列表顺序模拟。新增节点、标题修改和同级重排由最终 `tree` 直接表达。路径从最终树消失但没有相应操作时，预检拒绝执行，防止拼写错误被解释为删除。成功执行后，`changes` 被清空。

### 3.3 分类页面

`content/categories` 是分类树的物化结果，同时保存不可由树文件替代的分类介绍正文。每个节点对应一个与目录同名的 Markdown 文件：

```yaml
---
title: <由分类树生成>
layout: doc
category: <由目录计算的完整路径>
order: <由分类树数组位置生成>
---
```

分类同步器只重建这些元数据和第一个一级标题，并保留正文及同目录资源。新增节点使用 `scaffolds/category.md` 的等价结构生成占位介绍页。前端仍读取现有分类目录，因此动态路由、热更新和组件无需维护第二套运行时路径逻辑。

### 3.4 站点设置

`site.yml` 保存网站名称、首页说明、头像、文章响应式字号、主页响应式字号和默认第三级分类。`content.defaultCategory` 在分类改名、移动或合并涉及该节点时同步更新；删除默认分类被拒绝。

## 4. 统一同步

根目录的 `blog.mjs` 是全部用户命令的统一入口。它只负责解析公开命令、检查必填参数并调用内部程序；文章和草稿操作进入 `scripts/blog.mjs`，分类操作进入 `scripts/categories.mjs`，网站操作进入 `package.json` 中不对用户公开的构建脚本。这样不会占用 `npm list`、`npm publish` 等 npm 自有命令，也不要求用户了解 npm 的参数转发规则。

`scripts/categories.mjs` 是分类结构的唯一高层写入入口。公开入口只有两个：

| 命令 | 写入边界 |
|---|---|
| `node blog.mjs sync` | 统一分类树、文章目录和文章 `category`，并运行完整内容检查 |
| `node blog.mjs undo` | 恢复最近一次成功分类事务涉及的树、分类页、文章、默认分类和同步状态 |

文章文件夹、文章 `category` 与 `category-tree.yml` 都是源内容，但职责互不重叠：文件夹是否存在决定文章是否存在，`category` 决定文章归属，分类树决定节点身份、显示名称、层级和顺序。分类页面的结构元数据、动态路由、目录、标签和搜索索引都是由这些源内容生成的结果。

### 4.1 `sync`

同步执行顺序如下：

1. 解析并验证完整分类树，再与当前分类页面计算出的规范树比较。
2. 分类树发生变化时，从当前节点建立身份表，按顺序模拟 `rename`、`move`、`merge` 和 `remove`，并检查模拟结果与最终 `tree` 完全一致。
3. 为原节点计算最终路径，据此更新受影响文章的 `category`、默认分类和分类站内链接；分类介绍正文和同目录资源在重建中保留。
4. 重新扫描 `content/articles`。新增文件夹加入文章集合，消失的文件夹从文章集合移除，文章中改变的 `category` 成为新归属；引用的有效分类路径不存在时补建相应节点和分类页面。
5. 两种源修改无法唯一合并时停止并报告冲突。例如分类树删除一个仍被文章引用的节点，而文章没有给出新的归属时，不自动猜测目标分类。
6. 运行 `check-content.mjs`。写入失败时恢复操作前文件；成功时更新同步状态、动态路由依赖和可撤销记录，并通知开发服务器刷新。
7. 比较同步前后的持久状态与实际文件，报告文章新增、删除和归属变化，分类操作及节点变化，默认分类变化和自动改写的文件。报告来自最终状态差异，不依赖执行了哪个内部分支。

直接删除一个文章文件夹属于源内容变化，不是分类事务。同步会从内部状态移除该文章并重新计算分类成员、标签、搜索和路由，但不会自动删除因此变空的第三级分类；分类可能仍有介绍正文，也可能准备接收后续文章。需要可恢复删除和删除前站内引用检查时，`node blog.mjs remove <文章文件名>` 把同一完整文件夹移入 `.trash`。

文章分类路径必须随节点身份变化更新，否则文章会继续引用失效路径。因此此处的“不移动文章”严格表示：不移动文章目录、Markdown 文件、图片和附件，不改变正文、标题、日期、标签、`articleId`、网址、`order` 或 `categoryNote`；只允许更新必要的 `category` 和明确匹配的分类站内链接。

`.category-history/state.json` 保存最近一次成功同步后的文章 ID 与分类路径，用于识别新增、删除和归属变化。新文章没有旧状态时以默认分类作为可撤销的原归属。无源内容变化时，`sync` 不写分类树、不触碰撤销记录，也不发送重复刷新。

### 4.2 `undo`

每次有实际写入的成功分类事务会替换 `.category-history/latest/`。记录包含：

- 操作前的完整分类页面目录；
- 操作前的 `site.yml`；
- 操作前的规范分类树；
- 受影响文章的操作前文件；
- 操作前的文章归属状态；
- 操作后各目标文件的 SHA-256。

撤销前先比较操作后哈希。任何相关文件在事务后再次改变时，撤销整体停止并列出冲突，不覆盖新内容。校验通过后，撤销同样以回滚副本保护恢复过程；最终内容检查失败时恢复到撤销前状态。成功撤销会消费 `latest`，因此接口只承诺撤销最近一次分类修改。

文章文件夹在同步前已经由用户删除时不属于同步器可以恢复的数据，因此 `undo` 不会重建它。文件系统删除需要由编辑器、系统回收站或版本控制恢复；通过 `remove` 移入 `.trash` 的文章使用 `restore article` 恢复。

### 4.3 并发和故障恢复

同步和撤销用 `.category-history/lock` 进行进程级互斥。锁记录进程号；仍存活的进程会阻止第二个写入者，异常退出留下的无效锁会在下次运行时清除。

分类目录先生成到项目 `.cache` 中，再在预检通过后替换。执行阶段的任何异常都会从待提交记录恢复分类页、站点设置和受影响文章；失败事务不覆盖最后一次成功撤销记录。删除操作仅针对已经解析并验证位于项目内的分类缓存、分类目录和历史目录。

## 5. 文章和草稿维护

`scripts/blog.mjs` 保留以下非分类职责：

| 操作 | 实现 |
|---|---|
| 新建文章 | 使用文件名建立同名目录和 Markdown，占位标题为文件名，分类为 `content.defaultCategory` |
| 新建草稿 | 在 `content/drafts` 建立相同文件单元，不加入路由、分类或搜索 |
| 发布草稿 | 把完整目录移入文章目录，补充正式元数据并校验，失败时回滚 |
| 文章改名 | 同步目录、文件、`articleId`、文章网址和站内文章链接 |
| 文章或草稿移除 | 检查引用后移动到 `.trash`，不永久删除 |
| 恢复 | 把选中的文章或草稿完整目录移回原位置 |

新建、直接删除或恢复文章后，下一次 `sync` 会更新文章集合与分类同步状态。分类变更始终与文章物理目录独立。

## 6. 内容读取和页面生成

`scripts/site-lib.mjs` 提供以下核心流程：

1. `readCategoryDefinitions()` 扫描物化分类页，按目录计算路径和父级，并按生成的 `order` 排序。
2. `readAllArticles()` 扫描具名文章文件夹并读取开头设置。
3. `buildCatalogData()` 验证文章指向第三级节点，再生成分类、文章、标签、面包屑和相邻文章数据。
4. 动态路由的 `index.paths.mjs` 为每个文章 ID 和分类路径生成静态页面参数。

具名源文件通过 `srcExclude` 排除在 VitePress 普通页面扫描之外。文章网址为 `/articles/<articleId>/`，分类网址为 `/categories/<完整路径>/`，标签页为 `/tags/`。

动态文章页面使用 `rebaseMarkdownResources()` 在内存中把相对资源地址换算到源文章目录。磁盘 Markdown 不改变，因此同目录图片同时兼容 Markdown Preview Enhanced 和网站。

前端通过 `virtual:blog-catalog` 读取目录数据。`HomeCategories.vue`、`CategoryIndex.vue`、`Breadcrumbs.vue`、`ArticleMeta.vue` 和 `TagIndex.vue` 不直接访问文件系统。左侧分类树由 `config.mjs` 根据同一份目录数据生成 VitePress 原生侧栏配置：四个第一级分类始终可见，当前分支自动展开，其余分支保持收起；折叠、活动项、桌面滚动和手机抽屉均由 VitePress 默认主题处理。

全文搜索插件从具名文章和分类源文件构建 MiniSearch 索引，避免动态路由模板只被索引一次。中文使用相邻二字分词，英文和数字按词分割；索引网址使用最终公开路径。

## 7. 开发服务器和构建

公开命令 `node blog.mjs server` 与 `node blog.mjs generate` 分别调用内部的 `dev` 和 `build` 脚本，两者共享 `prepare:site`：

```text
sync → content:check → settings → tikz
```

因此本地预览和 GitHub Pages 构建都先统一分类树与文章状态，再使用同一份分类页面、主题和 Markdown 配置。自动同步为无变化操作时不写盘。

开发服务器优先监听 `127.0.0.1:5173`。`scripts/dev-server.mjs` 通过 `/__blog_status` 识别已经运行的本项目服务器；5173 被其他程序占用时，统一命令入口在 5173 至 5193 中选择第一个空闲端口，并通过 `BLOG_DEV_PORT` 传给 VitePress。静态产物预览以相同方式在 4173 至 4193 中选择端口。内容维护程序在开发端口范围内寻找本项目服务器，再向 `/__blog_refresh` 发送刷新通知。`node blog.mjs close` 只向通过身份检查的本项目开发服务器或静态预览发送 `/__blog_close`，由 Vite 关闭监听器和文件监视器；它不按端口结束未知进程。所有实际启动的 Vite 服务都启用 `strictPort`。

正文修改使用普通热更新；标题、日期、标签、分类、顺序或分类页变化时，虚拟目录模块失效并刷新页面。服务器未运行时，刷新通知安静失败。

具名文章 Markdown 在开发期间新增、移除或改变元数据时，目录插件先以独立进程执行无重复刷新通知的 `sync`，再重新计算文章签名和动态路由。文章保存为新分类路径时，缺失分类页会在目录模块重载前生成；删除文章文件夹时，相应路由、分类成员、标签和搜索记录会失效。同步失败会保留最后一次有效页面并把原因交给 Vite 错误输出。

新增、删除或改名具名源文件时，文件监听器更新时间戳模块，使 VitePress 重新计算动态路由清单，而不重启端口进程。

## 8. Markdown、公式和 TikZ

VitePress Markdown 配置启用 MathJax 3、AMS 编号、换行和图片延迟加载；关闭自动排版替换、自动链接和代码行号。`.crossnote/style.less` 与主题生成 CSS 共用 `site.yml` 中的文章正文字号，保证 Markdown Preview Enhanced 与网站具有相同的响应式字号基准。

文章字号和主页字号都把手机值、电脑值分别作为 390px、1440px 视口宽度的边界值，通过 CSS `clamp()` 线性插值；边界外保持配置值。文章正文、文章标题、章节标题、公式和以字符数计算的阅读宽度使用同一个文章字号基准。主页分类与最近更新区域使用主页字号基准。顶部导航、左侧分类目录和右侧文章目录属于固定界面，不随文章字号放大，以免压缩正文。

MathJax 处理行内公式、独立公式和 AMS 环境。`content/.vitepress/markdown-mpe-math.mjs` 用 Markdown Preview Enhanced 的定界符规则替换 `markdown-it-mathjax3` 的严格行内规则：定界符内侧允许空格，公式内容送入 MathJax 前会去掉首尾空格，转义的美元符号仍作为正文。兼容规则还会拒绝把含有未转义行内 `$...$` 的整段正文误认成一个 `$$...$$` 独立公式；这项处理只发生在内存中的网页解析过程，不修改文章文件。主题只让实际超出父容器的公式进入横向滚动状态，避免短公式出现无意义滚动。独立公式的溢出限制在自身区域，不扩大页面根宽度。

`render-tikz.mjs` 只扫描以下代码块：

````markdown
```tikz {embedFontCss=true}
...
```
````

源码规范化后计算 SHA-256，SVG 缓存在 `.cache/tikz/<hash>.svg`。检测到 `tikzcd` 环境时自动加入 `tikz-cd` 包；生成器扫描 SVG 字体并输出字体 CSS。主题按 SVG 自然比例显示交换图，并以正文宽度为上限。

## 9. 校验

`scripts/check-content.mjs` 检查：

- 分类目录名、层级、父级、标题、完整路径和同级顺序；
- 默认分类存在且位于第三级；
- 文章目录、`articleId`、标题、分类和同分类文章顺序；
- 文章本地图片与附件存在且路径不越出文章文件夹；
- 头像路径、替代文字和裁切模式；
- 文章与主页的手机、桌面字号范围及其大小关系；
- 空的非默认第三级分类，并以警告报告。

`categories.mjs` 在写入前另行检查分类树格式、操作序列、最终节点集合、大小写冲突、文章最终归属、默认分类和删除引用。写入后仍必须通过完整内容检查。

`node blog.mjs check` 依次检查公开入口、维护脚本和 VitePress 配置的 JavaScript 语法，再运行内容检查。该命令不执行分类同步，也不写入项目文件。

## 10. GitHub Pages

`site.yml` 的 `deploy` 节点是发布配置的唯一来源：`repository` 是源码仓库地址，`branch` 是接收源码的分支，`basePath` 是项目网站在域名后的固定路径，`siteUrl` 是发布后的完整网址。公开命令 `node blog.mjs deploy` 调用 `scripts/deploy.mjs`，依次完成配置校验、带正式路径的整站构建、远程仓库一致性检查、`git add -A`、提交和推送。构建失败时不会修改 Git 状态；远程仓库地址与配置不一致时停止，避免上传到错误位置。首次部署且仓库没有提交时，命令会把本地分支改为配置中的分支。成功输出包含变更类型计数、提交编号、仓库、分支、Actions 页面和网页地址。

`.github/workflows/deploy-blog.yml` 在 `main` 或 `master` 分支的 `site/**` 发生变化时使用 Node.js 20 和 `npm ci`，随后执行与本地相同的 `node blog.mjs generate`，上传 `content/.vitepress/dist` 并部署到 GitHub Pages。工作流通过 `BASE_PATH=/Blog/` 和 `SITE_HOSTNAME=https://elenalee20251212-a11y.github.io/Blog/` 注入项目网站路径；本地部署命令从 `site.yml` 注入相同值。本地不保存发布密钥。

根域部署使用 `base: /`；仓库子路径部署通过 `BASE_PATH=/repository-name/` 注入。主题和动态路由生成的内部链接使用 `withBase()`，因此两种部署方式共用源码。

## 11. 修改规范

- 新增文章设置时，需要同步修改 `site-lib.mjs`、`check-content.mjs`、相关组件和两份文档。
- 新增文章或分类同步行为时，必须扩展统一的 `sync` 事务，并同时补充预检、失败回滚、成功撤销和无变化测试；不得重新增加需要用户选择同步方向的入口。
- 分类同步不得移动文章目录或附件，也不得修改与分类无关的文章设置。
- 分类页结构元数据只能由同步器写入；分类介绍正文必须在重建、移动和撤销后保持。
- 正文 CSS 变化需要同步检查 `.crossnote/style.less`、桌面双目录、390px 手机布局、公式溢出和 TikZ 缩放。
- VitePress 或 MathJax 升级后需要重新检查动态路由、搜索、左侧分类树、右侧本文目录、移动端抽屉和页面根宽度。
- 构建产物、缓存、生成的站点设置 CSS 和 TikZ 字体 CSS 不接受手工编辑。
